# Theo audit, 2026-11-01

What the app looked like when this pass started, screen by screen, and the real causes behind Addy's complaints. Baseline screenshots are in `docs/evidence/baseline/`.

## The complaints and what was actually wrong

| Addy said | Real cause |
|---|---|
| "UI not clicking", "click 2 times" | SwiftUI's own containers refuse the first click in a window that isn't frontmost: `PlatformGroupContainer` and `HostingScrollView` return false from `acceptsFirstMouse`, across about 60% of the window (837 of 1,376 sampled points). The first click only activated the window. |
| | Settings was a separate window that could open behind the main one, and it ignored the page it was asked for when already open. |
| | The spark's click catcher sat above every app wherever the spark rested, and took clicks meant for what was under it. |
| | A streaming reply could crash the app (`prefix` with a negative count on the first chunk). |
| "Subscription connection from terminal is corrupted, no T3 link" | Settings › Coding had no sign-in button at all, only text. T3 Connect was buried in Screen. Sign-in meant leaving the app. Harness detection missed npm's global folder. |
| "No place to add API keys" | The page existed, but it only stored keys. Nothing used them, and the first click problem made its fields feel dead. There was no engine, voice or harness that could run on a key. |
| "Bots are still not good" | Only Theo could start a run, and only by writing a prompt block. No Stop, no live card, no files changed, no push or PR tested. A run on any harness but T3 had no result card. |
| "Still many icons are not there" | Every SF Symbol resolved: the missing ones were harness and provider icons drawn as generic glyphs, and connector logos fetched over the network. There were no bundled logos. |
| "Clicky not good enough" | Clicky couldn't read a browser that wasn't frontmost, so research and article highlights failed on Theo's own monitor, which is where it opens things. Wake word heard "hey Theo" as "hey Siri" most of the time. |
| "UI still shitty, vibe coded" | 25 font sizes against 7 in the design, 11 radii against 4, 57 hard-coded colours, a chat column at 14pt on 105 characters a line, three different chat headers, a sidebar 24 fps icons fighting for attention, and light mode built from dark mode's hard-coded whites. |

## Screen by screen, at the start

- **First run:** eight steps, old styling, sign-in left the app, "Add a key" landed on Home.
- **Home:** org chart cut off by a horizontal scroll, one line to one card.
- **Sidebar:** seven saturated tiles moving constantly, 15 to 30% of a core when idle; 72pt of empty space on top.
- **Bot chat:** 14pt text, tables as raw pipes, blockquotes with a literal `>`, routine JSON in the chat, reply jumps when typing ends, empty chats stuck to the bottom.
- **Bot settings:** 5pt strips on both sides, truncated chips, three picker widths.
- **New bot:** form wider than its sheet on a Mac with all harnesses installed (the common case): text cut off on both sides. No model choice; a new Claude bot started on Opus.
- **Clicky:** its toggle sat under the settings button, so half of it opened settings.
- **Team page:** labels 8pt out of line, unequal cards.
- **Connectors:** raw system colours, two pills per row, Connect shifted the labels, hard to read in light mode.
- **Settings:** separate window, no logos, API keys unusable, Coding with no buttons.
- **Light mode:** muddy code cards, vanishing logo tiles, unreadable badges.

All of this was found by clicking the installed app and looking at screenshots of its window. What's been done about each one is in `docs/TEST-MATRIX.md`.
