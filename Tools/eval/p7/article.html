Swift concurrency, explained

Concurrency in Swift starts from the idea that work can wait without holding up the whole program.

Async functions can suspend without blocking a thread, so the system can run other work while they wait.

A small example helps: a function that downloads an image awaits the network and returns when the bytes arrive.

Actors serialize access to their mutable state, so data races are caught at compile time instead of in production.

Actors do not remove the need to think about ordering, but they make the shape of shared state explicit.

Structured concurrency keeps child tasks inside the scope that started them, so cancellation and errors flow outward.

Sendable marks types that are safe to pass across concurrency domains, and the compiler checks the conformance for you.

Start with async and await in your own code, add actors where state is shared, and let the compiler guide the rest.
